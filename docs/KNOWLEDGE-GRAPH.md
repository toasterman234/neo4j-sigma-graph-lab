# Knowledge Graph — authoritative project doc

This is the single authoritative document for Ben's Neo4j knowledge graph:
what it is, how it's layered, how each layer got there, and how to manage it.
If this doc and someone's memory disagree, this doc wins — then fix this doc.

**Database:** Neo4j 5 on the ZimaOS box (`ben-neo4j-neptune-baseline` container),
Bolt `zimaos:17687`, database `neo4j`. Credentials live in the repo-root `.env`
(0600, gitignored) — never in this doc.

**Code:** this repo (`toasterman234/neo4j-sigma-graph-lab`).
**Viewer:** `/explore` tab (kind-clustered, phone-first) and `/sigma-explorer`
(raw graph). Both read-only.

## The two-layer model

```
┌─────────────────────────────────────────────────┐
│ BASELINE — read-only, never written by us       │
│ AWS Bedrock extraction migrated from Neptune:   │
│ Entity (7,548) · Chunk (1,914) · DocumentId     │
│ (234) · SemanticEntity pilot (36)               │
│ This is evidence plumbing. Not a UI.            │
└──────────────────┬──────────────────────────────┘
                   │ projected into the SAME database,
                   │ marked and wipeable, baseline untouched
                   ▼
┌─────────────────────────────────────────────────┐
│ PROJECTIONS — rebuildable, source-marked layers │
│ :ProjectionNode + _projection = source name     │
│ vault notes · Things 3 · muse notes · foundation│
│ central-ops docs · spine archive · social likes │
│ These are the human-browsable layers.           │
└─────────────────────────────────────────────────┘
```

**Why this shape:** the baseline preserves the AWS extraction investment
(chunks with source text, entities, provenance). Projections put Ben's actual
world — goals, decisions, tasks, notes, docs — next to it as typed,
browsable nodes without ever mutating the baseline.

## Conventions (hard rules)

1. **Baseline is read-only.** No projection script writes a node or edge that
   isn't labeled `:ProjectionNode`. Ever.
2. **Every projection node** carries `:ProjectionNode` plus a source label
   (e.g. `:VaultNote`, `:FoundationNode`) and a `_projection` property naming
   the source (`vault-live`, `things3`, `muse-notes`, `foundation`,
   `central-ops-docs`, `spine-archive`, `twitter-likes`, `youtube-likes`,
   `vault-v2`).
3. **Wipe/rebuild per layer**, never touching anything else:
   `MATCH (n:ProjectionNode {_projection:'<source>'}) DETACH DELETE n`
   then re-run that layer's ingest script.
4. **Browser API stays read-only.** All writes go through server-side ingest
   scripts in `frontend/scripts/`. No exceptions.
5. **Canonical sources are the truth.** The graph is a projection; vaults,
   Things database, foundation (TerminusDB), and social exports remain
   authoritative. Rebuild from them, don't patch the graph by hand.
6. **Register every layer** in the table below when you add one, and re-run
   the census script.

## Semantic layer status

Two things exist today; neither is the finished semantic knowledge graph.

1. **Baseline pilot (36 nodes, 67 edges).** `SemanticEntity` nodes typed
   Project (10), Service (7), SyncOption (5), Platform (4), DecisionState (3),
   System (2), Process (2), Decision (2), Task (1). All 36 carry `EVIDENCED_BY`
   edges to `Chunk` nodes (provenance is real edges, not just ID properties),
   plus 31 typed inter-semantic edges (USES, HAS_OPTION, IN_STATE, HOSTED_ON,
   INTEGRATES, SUPPORTED_ON, RELATED_TO, HAS_DECISION, FOLLOWED_BY).
   Tagged `enrichment_scope: bounded-pilot`. This is a pilot, not coverage.
2. **Foundation projection (701 nodes, ~1,190 edges).** This is the working
   world model: goals, decisions, ideas, preferences with the governed
   snapshot's own typed relationships. The closest thing to the "human
   knowledge graph" today.

**Roadmap:** the full semantic interpretation layer — Decision supersedes
Decision, Observation supports Decision, repository implements System, with
every assertion evidence-linked to chunks. Not started; the pilot + projections
are the substrate it builds on.

## Managing the graph

**Add a layer:**
1. Write the ingest script in `frontend/scripts/` (read-only reads of the
   canonical source; all writes labeled per the conventions above).
2. Support `--dry-run`. Wipe-before-write per layer unless there's a reason
   not to.
3. Add a row to the layer registry above.
4. Run `node frontend/scripts/graph-census.cjs` to refresh the census block.
5. Commit on a `work/*` branch; merge when verified.

**Rebuild a layer:** wipe Cypher from convention 3, re-run its script.

**Refresh the census:** `node frontend/scripts/graph-census.cjs`
(reads `.env` for Bolt creds, read-only queries, rewrites the census block
between the markers, prints what changed).

**Saved Jev runs** live in `frontend/.data/graph-lab.sqlite` (not in Neo4j).
